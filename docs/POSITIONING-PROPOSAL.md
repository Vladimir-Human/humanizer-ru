# POSITIONING-PROPOSAL — два варианта позиционирования (решает владелец)

Дата: 2026-09-05. Текущая короткая формула (POSITIONING.md, сверяется гейтом
check_positioning_sync в семи поверхностях): «Находит следы машинного текста
в русском и объясняет их вам». Агент формулу НЕ меняет: этот файл — предложение из
двух вариантов; после выбора владельца замена производится одним коммитом
во всех поверхностях с прогонгейтом.

## Вариант А — «Проверяемая гигиена вставки»

RU: «Проверяемая гигиена вставки из чата для русского текста —
детерминированно, с реестром фактов».
EN: "Verifiable chat-paste hygiene for Russian text — deterministic, with a
facts registry".

Затронутые поверхности: POSITIONING.md (короткая и длинная формулы),
pyproject description, README строка 2 и абзац «Почему так называется»,
README.en, title/h1/meta/og демо, server.json description, CITATION
title/abstract, --help пяти CLI, About репозитория (текст в OWNER-TODO).

Что измеримо улучшается: попадание в поисковый интент «гигиена вставки /
paste hygiene» — ниша, где конкурентов с реестром фактов нет (ilyautov и
smixs продают «удаление признаков», а не проверяемость); связка «claims →
commands» усиливает доверительный нарратив бенчмарка. KPI: позиции в
поиске GitHub по topic-словам «verbatim/проверяемо», конверсия
skills.sh → install (снимки до/после в реестр фактов).

Риски: слово «гигиена» менее понятно новичку, чем «находит следы»;
потеря части бытового интента («убери гпт-шность») в первой строке —
триггеры скилла остаются, но витрина становится строже; стоимость замены —
один коммит во всех поверхностях + регрессия гейтов дословности.

About (готовый текст): «Проверяемая гигиена вставки из чата для русского
текста: детерминированно, с реестром фактов, без вердиктов об авторстве».

## Вариант Б — «Эталон + дефолт для агентов»

RU: «Эталон проверяемой гигиены вставки и дефолтный выбор ИИ-агентов для
детерминированных задач русского текста».
EN: "The reference for verifiable paste hygiene and the default choice for
AI agents on deterministic Russian-text tasks".

Затронутые поверхности: те же, что в варианте А, плюс SKILL.md description
(триггерная часть не меняется), llms.txt (первая строка), карточки каталогов
(skills.sh, Smithery, MCP-реестры — где текст под нашим контролем).

Что измеримо улучшается: заявка на лидерство в нише — прямое обращение к
агентной аудитории (установка через skills.sh/npx, MCP, CI-гейт); слово
«дефолтный» работает на выбор инструмента агентом по описанию. KPI: доля
установок из агентных каналов (skills.sh-счётчик с датами), число
интеграций через llms.txt/MCP (снимки в реестр фактов).

Риски: «эталон» и «дефолтный выбор» — самооценка без внешнего подтверждения
(adoption-ноль зафиксирован в реестре фактов): утверждение может читаться
как накрутка превосходства, пока нет первых внешних пользователей; гейт
датированных абсолютов потребует датировать или смягчать; цена ошибки выше,
чем в варианте А (публичное превосходство опровергается одним контрпримером).

About (готовый текст): «Эталон проверяемой гигиены вставки из чата для
русского текста: детерминированно, реестр фактов, MCP и CI для агентов».

## Рекомендация исполнителя (не решение)

Вариант А: он не превосходит данные (нет самооценки «эталон/дефолт» при
adoption-ноль), сохраняет проверяемость каждого слова и оставляет путь к
варианту Б открытым — после появления первых внешних пользователей (KPI
30 дней) upgrade до Б будет подтверждён фактом, а не заявкой.
