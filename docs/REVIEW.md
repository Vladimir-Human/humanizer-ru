# Регламент review

Документ отвечает на один вопрос: что должно быть сделано, чтобы изменение
попало в main. Он не о вежливости и не о стиле кода, а о том, какие
доказательства обязан предъявить автор изменения.

## Почему он существует

До v3.6.0 review держался на памяти. Последствия были измеримыми:

- Гейт реестра источников год сравнивал список с самим собой и пропускал любой новый маркер.
- 13 из 29 примеров «До/После» дописывали читателю факты, которых не было в исходнике.
- Eval-корпус и сборка архива существовали, но не запускались автоматически.

Всё трое прошли не из-за небрежности, а потому что нигде не было записано, что их надо проверить.

## Главное правило

**Новый гейт принимается только вместе с доказательством того, что он умеет падать.**

Проверка, которая никогда не падала, не доказана. Допустимые формы доказательства:
`--selftest` с отрицательными случаями или вывод прогона на специально сломанном входе,
приложенный к PR.

## Три класса изменений

### Класс A — ядро

Паттерны редактуры, дерево решений, границы ложных срабатываний, жанровые правила.

Обязательно:

- Обоснование: почему это признак машинного текста, а не вкусовая правка.
- Пример «До/После», проходящий `check_examples.py`. Если пример показывает подстановку
  авторских данных — пометка «После (с фактами автора)».
- Оба README обновлены, если меняется число паттернов или состав разделов.
- Запись в CHANGELOG.
- С фазы 2: прогон `eval/blind_eval.py` до и после, метрики не просели.

### Класс B — быстрый слой

Новый regex-маркер или изменение существующего.

Обязательно:

- Три фикстуры: позитивная, негативная, граничная.
- Запись в `research/fixtures/marker-sources.json`: immutable-ссылка, дата обращения,
  дословный образец, класс доказательства.
- Проверка скорости: выражение не дольше 0.5 с на входе в 30 000 символов. Машинно проверяется `scripts/check_perf.py` (четыре синтетических корпуса плюс короткая ловушка откатов).
- Проверка на ложные срабатывания: прогон по контрольной группе человеческих текстов
  из `research/validation/human/`; состав корпуса зафиксирован в
  `eval/manifest.v1.json`.

Маркер не становится жёстким только потому, что он новый.

### Класс C — инфраструктура

CI, скрипты, гигиена репозитория, документация.

Обязательно:

- У валидатора есть `--selftest`, и он вызывается в CI отдельным шагом.
- Доказательство падения гейта (см. главное правило).
- Никаких внешних зависимостей Python: только стандартная библиотека.

## Что проверяет машина

Перечисленное никогда не проверяется глазами — это работа CI.

| Проверка | За чем следит |
|---|---|
| `check_spec.py` | Соответствие формату Agent Skills, имя совпадает с каталогом |
| `check_budget.py` | Лимиты name/description/compatibility, размер тела SKILL.md |
| `check_docs.py` | Версии в документации согласованы, тег установки существует |
| `check_markers.py` | Все regex ловят свои образцы на трёх уровнях |
| `check_fixture_sources.py` | У каждого нового маркера есть запись в реестре |
| `check_examples.py` | Примеры До/После не дописывают фактов |
| `check_corpus.py` | Сырой корпус исследования не повреждён |
| `check_release.py` | Архив собирается и содержит только разрешённое |
| `scan_soft_signals.py` | Мягкие признаки считаются по порогам дерева решений, жанровые исключения не теряются |
| `check_all.py` | Чек-лист выполняется одним прогоном; без корпуса гейт даёт SKIP, а не ложный PASS |
| `eval/run_eval.py` | Нейтральный корпус не даёт регрессий |
| `eval/blind_eval.py` | Механические метрики эффекта на парных прогонах |
| self-scan | Сама документация не содержит маркеров |
| no-anglicisms | Запрещённые штампы в документации |

## Что проверяется только глазами

Машина этого не умеет, поэтому список короткий и обязательный:

1. Правда ли то, что написано. Скилл о честности текста не может преувеличивать свои возможности.
2. Нет ли обещания того, чего мы не проверяли. Отдельно: заявления об обходе детекторов
   недопустимы ни в какой форме.
3. Совпадают ли числа в тексте с реальным состоянием репозитория.
4. Не стал ли пример хуже после правки — гейт ловит дописанные факты, но не вялость.

## Чек-лист релиза

Быстрый путь — те же гейты одним прогоном (в полном клоне репозитория
исхода SKIP быть не должно, он законен только в поставке без корпусов):

```bash
python3 scripts/check_all.py
```

Те же шаги по отдельности:

```bash
python3 scripts/check_spec.py SKILL.md --strict --expect-dir humanizer-ru
python3 scripts/check_budget.py SKILL.md --expect-dir humanizer-ru
python3 scripts/check_docs.py && python3 scripts/check_markers.py --parity
python3 scripts/check_examples.py && python3 scripts/check_corpus.py
python3 scripts/check_fixture_sources.py research/fixtures/marker-sources.json
python3 eval/run_eval.py && python3 eval/blind_eval.py --selftest
python3 scripts/check_release.py --root . --build dist/humanizer-ru.zip
python3 scripts/check_release.py --verify dist/humanizer-ru.zip
```

Далее: тег `vX.Y.Z`, заметки к релизу, проверка страницы каталога.

**Приложить собранный архив к выпуску обязательно.** Обе витрины в разделе
установки велят скачать со страницы Releases именно `humanizer-ru.zip`: у него
`SKILL.md` лежит в корне, поэтому переупаковка не нужна. Автоматически он туда
не попадает — `release-check.yml` кладёт архив только в артефакты прогона, а не
в ассеты выпуска. Если шаг пропустить, инструкция установки будет вести на файл,
которого на странице нет.

```bash
gh release create vX.Y.Z --title "vX.Y.Z" \
  --notes-file research/RELEASE-DRAFT-vX.Y.Z.md dist/humanizer-ru.zip
# либо к уже созданному выпуску:
gh release upload vX.Y.Z dist/humanizer-ru.zip
```

Сверить все числа новой записи CHANGELOG с фактическим выводом валидаторов.
Запись пишут до последней правки кода, поэтому счётчики самопроверок в ней
устаревают молча: в 3.7.4 заявленное «23 → 26, три случая» разошлось с
фактическим 27 после того, как в гейт добавили четвёртый случай. Гейта на это
нет и не будет — прошлые записи журнала законно называют прошлые числа,
поэтому сплошная проверка невозможна. Сверяется руками, по выводу прогона.


Проверить после публикации:

```bash
gh release view vX.Y.Z --json assets --jq '.assets[].name'   # ожидается humanizer-ru.zip
```

## Когда изменение отклоняется

- Добавляет маркер без записи в реестре доказательств.
- Добавляет проверку, которая не может упасть.
- Увеличивает тело SKILL.md без переноса части в `references/`.
- Содержит пример, где правка дописала факты без пометки.
- Меняет ядро без прогона слепой оценки (с фазы 2).
