# Q2: решение по коллапсу — lint-only как продуктовая линия

Вопрос: выделять ли lint-only (детерминированное снятие артефактов без
перезаписи) как отдельную продуктовую линию, и в какой форме?

Дата предрегистрации: 2026-08-28 (`preregistration.md`, хеш в
`evidence/corpus-freeze.sha256`, 82 файла). Замеры:
`evidence/stats.json`. Консилиум: `evidence/consilium.json` (qwen3.8-max + kimi/kimi-k3, единогласен).

## Правило коллапса (дословно из предрегистрации)

«Блокирующий гейт: lint-чистка не меняет ни байта на 40 человеческих
контролях И на 9 файлах пробы Q3 (в пробе нет истинных артефактов;
изменение байта = порча). Нарушение гейта убивает H-MODE и H-CI до
устранения причины. Гонка: побеждает H-CI (расширение action/ до
автофикса), если гейт пройден И повторный скан M+-файлов после чистки
даёт 0 маркеров. Побеждает H-MODE (отдельный режим скилла), если гейт
пройден И сегмент «только маркеры» (M+, S−) ≥ 20% ИИ-корпуса (≥ 7 из
33). Иначе побеждает H0: lint остаётся внутренним слоем перезаписи,
отдельная точка входа не выделяется. Порядок: H-CI проверяется первым;
тай-брейков нет — условия упорядочены по специфичности (байтовый
инвариант первичен порогового сегмента). H-EDIT и H-DEMAND в гонке не
участвуют (вне измеримости цикла): рамки попадают в ограничения
решения. Внедрение победителя (если не H0) — отдельным changeset'ом;
решение о продуктовой поверхности фиксируется в decision.md с явной
пометкой о передаче выбора исполнителю владельцем (2026-08-28).»

## Матрица «гипотеза × доказательство»

| Гипотеза | Условие | Замер | Исход |
|---|---|---|---|
| Блокирующий гейт | 0 байт на 40 контролях И 9 пробах | 0/40 файлов изменено; 0/9 проб изменено | **пройден** |
| H-CI (CI-автофикс) | гейт И 0 маркеров после чистки M+-файлов | 3/3 M+-файла чисты после чистки (residual=0) | **победитель** |
| H-MODE (режим скилла) | гейт И M+ ≥ 20% (≥7/33) | M+ = 3/33 (9.1%) | не прошла |
| H0 (внутренний слой) | иначе | — | не достигнут |

Аудит прогнозов: P1 ✓ (0/40), P2 ✓ (0/9), P3 ✓ ровно (3/33: gemini/02
gemini_span ×3, gemini/03 gemini_span ×7, le-chat/01 zero_width BOM ×1),
P4 ✓ (3/3 чисты), P5 ✓ (S+ пуст: features max 2 < 3). Пять из пяти
прогнозов подтверждены; сегмент «ничего» = 30/33.

Консилиум (qwen3.8-max + kimi/kimi-k3, арбитр deepseek-v4-pro-0813):
единогласен — коллапс состоялся, победитель H-CI; qwen независимо
верифицировал заморозку (82/82 хешей) и хронологию (правило 11:14 →
фикс гарда 11:22 → Q3-перепрогон 11:35 → заморозка 11:41 → данные
11:41); kimi подтвердил состав M+ дословно. Расхождений в исходе нет.

## Победитель и механическое срабатывание правила

**H-CI: расширение CI-экшена до автофикса** — опциональный режим `fix`
в `action/action.yml`: детекция маркеров класса A → чистка только
помеченных файлов текстовым путём filemarks → рабочий каталог остаётся
с изменениями для коммита вызывающим workflow. Внедрение — отдельным
changeset'ом (этот репозиторий, этим же циклом; см. ниже «Внедрение»).

## Отколлапсированные ветки

- **H0 (внутренний слой)** — убита: гейт пройден и полнота снятия
  измерены, у H0 нет различающего преимущества перед измеренным
  байтовым инвариантом. Воскрешение: корпус, где lint меняет байты на
  контролях (нарушение гейта) — тогда автофикс недопустим, слой
  возвращается внутрь перезаписи.
- **H-MODE (отдельный режим скилла)** — убита порогом: сегмент «только
  маркеры» 3/33 (9.1%) < 20% — ниша слишком мала для отдельной точки
  входа; G5 (B>D 14/14) дополнительно ограничивает lint-обещание.
  Воскрешение: корпус, где ≥ 20% ИИ-файлов несут только маркеры без
  мягкого слоя (например, корпуса с heavy copy-paste из чат-UI).
## Живые ветки вне гонки

- **H-EDIT, H-DEMAND** — живы (evidence_needed): токен-дифф вне
  маркерных спанов (артефакты G5 вне репозитория); телеметрия спроса.

## Внедрение (победитель H-CI)

Реализовано в том же цикле отдельным changeset'ом:

- `action/action.yml`: новый инпут `fix` (по умолчанию `false` —
  поведение существующих пользователей не меняется); в режиме `class-a`
  при `fix: true` каждый файл с маркером класса A чистится текстовым
  путём filemarks (text_layer: Layer A + MARKUP — тем самым путём,
  что валидирован замерами этого цикла), файлы без маркеров не
  трогаются вовсе; изменённые файлы остаются в рабочем каталоге —
  коммит делает вызывающий workflow. Путь вызывается напрямую
  (text_layer), а не через CLI filemarks --clean: CLI маршрутизирует
  .md в контейнерный путь (метаданные frontmatter), который не снимает
  текстовые маркеры — обнаружено smoke-прогоном внедрения и исправлено
  до коммита; smoke-прогон после исправления: маркер gemini_span снят
  (markup=2), чистый файл не тронут, повторный скан 0.
- Документация: README RU/EN — строка инпута `fix` с измеренными
  гарантиями и границами.

Границы внедрения (наследие оговорок консилиума, публикуются с
фичей):

1. Нейтральность измерена на 49 файлах репозитория (LF); легальные
   невидимые вне корпуса (SHY, BOM, PUA) чистятся по дизайну Layer A —
   автофикс целится в тексты с копипастом из чат-интерфейсов, не в
   вёрстку.
2. Чистка помеченного файла нормализует переводы строк к LF (свойство
   текстового пути filemarks); файлы без маркеров не перезаписываются.
3. Паритет снятия на живом корпусе подтверждён для gemini_span и
   zero_width (11 хитов трёх файлов); остальные классы — фикстуры и G5.
4. Спрос не измерялся (H-DEMAND): победа H-CI — capability-evidence;
   автофикс — опция, не замена перезаписи (G5: B>D 14/14).
