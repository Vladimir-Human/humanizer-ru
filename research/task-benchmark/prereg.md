# Предрегистрация: бенчмарк задачи (task benchmark) — 2026-09-08

Статус: ЗАМОРОЖЕНА до первого оцениваемого прогона. Правка после прогона
запрещена: изменение критериев = новая версия предрегистрации и новый
протокол результатов; история не переписывается. sha256 этого файла
записывается в каждый протокол результатов и сверяется гейтом
`scripts/check_task_benchmark.py --verify`.

## Что измеряется

Задачный уровень продукта: единица измерения — документ, артефакт или
операция (не «корпус в среднем»). Бенчмарк измеряет правильность
собственных операций продукта и воспроизводимость протокола сравнения;
утверждений о лидерстве в нише не делает (лидерство требует независимых
внешних наблюдений — рамка `LEADERBOARD.md`).

## Операции и критерии

### O1 — детекция артефактов вставки (единица: документ)

- Корпус: `eval/manifest.v1.json` (52 документа: 26 human, 24 ai,
  2 boundary), sha256 каждого сверяется перед прогоном.
- Протокол: `eval/run_eval.py` (reference) — существующий замороженный
  протокол лидерборда.
- Критерии PASS/FAIL:
  - человеческие документы (26): находок маркеров классов A/B — 0;
    любая находка = ложное обвинение, фиксируется как ПОТЕРЯ;
  - boundary-контроли (2): поведение как заявлено в манифесте;
  - AI-документы (24): число находок — наблюдение (per-document ground
    truth отсутствует; заявленные в манифесте ожидания сверяются, прочие
    числа публикуются как наблюдения без PASS/FAIL).
- Компаратор: приколотый линтер smixs/humanizer-ru
  (`eval/candidates/smixs_lint_pinned.py`, коммит 91f70df, MIT) через
  `eval/run_eval.py --candidate eval/candidates/smixs_runner.py` на том
  же корпусе той же даты. Сопоставимы ТОЛЬКО ось ложных срабатываний на
  человеческих документах и boundary-контроли (счётчики правил
  несопоставимы: smixs суммирует все правила, reference — только
  маркеры A/B; граница зафиксирована в `research/leaderboard/README.md`).

### O2 — контролируемая очистка (единица: артефакт/файл)

- Корпус: `tests/fixtures/*.txt` (11 файлов реальных образцов) +
  синтетический документ с защищёнными областями.
- Протокол: `humanizer-clean` (text_layer.clean_supported) на каждом
  документе; после очистки:
  1. поддерживаемые артефакты absent (повторный scan);
  2. факты целы: `facts_diff` lost=0 и changed=0 (added допускается
     только из снятия маркеров, фиксируется);
  3. защищённые области (fenced/frontmatter/инлайн-код) не изменены;
  4. rc и статус соответствуют контракту.
- Компаратор: ОТСУТСТВУЕТ (smixs — линтер без очистки). Отсутствие
  компаратора публикуется как отсутствие, не как победа.
- Любое нарушение 1–4 на любом документе = ПОТЕРЯ, публикуется.

### O3 — сверка фактов (единица: операция/пара)

- Корпус: замороженный набор пар (идентичная, потеря числа, добавление,
  инверсия отрицания, перестановка сумм (граница метода), смешанный
  разряд «5 миллионов»/«пять миллионов», дробь с разрядом, диапазон с
  разрядом (граница), порченый UTF-8 (код 2)).
- Критерий: вердикт (lost/added/changed/identical/rc) равен ожидаемому
  на каждой паре; любое расхождение = ПОТЕРЯ.
- Компаратор: отсутствует (детерминированная сверка фактов — операция
  без публичных аналогов на стандартной библиотеке; утверждение
  проверяется отсутствием, а не перебором — статус «не измерено»).

### O4 — выбор операции агентом (единица: задача; отдельный замороженный
протокол)

- Протокол: 6 задач в `research/task-benchmark/o4-tasks.json` (файл
  задач frozen в коммите предрегистрации); исполнитель читает задачи из
  файла сам (пересказ координатором запрещён — AGENTS.md); ответ —
  JSON {task_id, tool, mode}; оценивается машинно против ключа
  (answer_key в том же файле).
- Сессии: живой API (модель и провайдер записываются в протокол
  нейтрально: модель, провайдер, температура; без внутренних ролей и
  локальных путей). Каждая сессия записывается дословно (prompt,
  ответ).
- Критерий: ≥5 из 6 задач — правильный выбор операции.
- ПРАВИЛО ОТСУТСТВИЯ: если живой API недоступен, критерий O4 получает
  статус BLOCKED с причиной; сессии не фабрикуются и не имитируются.
  BLOCKED публикуется в отчёте и в итоговой таблице DONE.

## Публикация потерь

- Все потери (любые FAIL любых операций) записываются в протокол
  результатов (секция `losses`) и в отчёт `report.md`; протокол без
  секции losses или с пустым прогоном отвергается гейтом.
- Интерпретации чисел, снятые позже, публикуются в `ERRATA.md`; данные
  не удаляются.

## Заморозка и воспроизведение

- Прогоны: `python3 eval/run_task_benchmark.py` (O1–O3) записывает
  `research/task-benchmark/results-<дата>.json` с sha256 этой
  предрегистрации; O4-сессии добавляются в тот же протокол секцией
  `o4` с дословными записями.
- Сверка: `python3 scripts/check_task_benchmark.py --verify
  research/task-benchmark/results-<дата>.json` — хеш предрегистрации,
  полнота прогона (все объявленные операции присутствуют), потери не
  скрыты, числа протокола пересчитываются из сырых записей.
- Самопроверка гейта: `--selftest` с негативами (чужой хеш
  предрегистрации, отсутствующий прогон, скрытая потеря, подменённое
  число).
