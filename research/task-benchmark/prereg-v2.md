## Почему v2 (раскрытие)

Прогон v1 выявил 7 потерь O2. Разбор каждой потери (пробы исполнены на
том же дереве, команды в `report.md`) показал расхождение критериев v1 с
ДОКУМЕНТИРОВАННОЙ семантикой продукта, а не дефекты продукта:

1. Потери фактов на `openai-pua.txt` (lost=8: числа 0/1) и аналогичные —
   это payload PUA-сносок и маркеров (U+EA01цифраU+EA02 и подобные):
   документированная семантика продукта — «payload маркеров копипасты не
   является фактом автора» (`edit_report._strip_markers`, сверка фактов
   инструмента humanizer-clean идёт через этот путь). Критерий v1
   применял «сырой» `facts_diff.diff(before, cleaned)`, который считает
   payload маркеров фактами, — измерение не того, что продукт обещает.
2. «Защищённые области изменены» на `injection-closing-tag.txt` и
   `injection-fake-permission.txt` — изменение URL-спана
   `https://x.com/post?referrer=grok.com` -> `https://x.com/post`:
   снятие utm/referrer-параметров внутри URL — документированное
   поведение (contract.v1.json, removal_guards маркеров). Критерий v1
   сравнивал ВСЕ защищённые спаны (включая URL и html-теги), тогда как
   guard контракта обещает байт-в-байт для fenced-блоков,
   YAML-frontmatter и инлайн-кода; проба подтвердила: эти три класса
   областей на обоих файлах не изменены.

Изменение критериев после прогона = новая версия предрегистрации и новый
протокол (правило v1, сохранено здесь дословно). Протокол v1 с потерями
публикуется целиком; потери v2 публикуются по тем же правилам.

## Отличия v2 от v1

Разделы O1, O3, O4, правила публикации потерь, заморозки и
воспроизведения — БЕЗ ИЗМЕНЕНИЙ (действуют из v1 дословно). Изменён
только критерий целостности O2:

### O2 (v2) — контролируемая очистка (единица: артефакт/файл)

Корпус тот же: `tests/fixtures/*.txt` + синтетический документ.
После `clean_supported` на каждом документе:

1. фикспойнт: повторная очистка не снимает ничего (поддерживаемые
   артефакты отсутствуют);
2. факты целы ПО ДОКУМЕНТИРОВАННОМУ ПУТИ продукта:
   `edit_report.facts_part(before, cleaned)` (marker-aware: payload
   маркеров не считается фактом автора) — lost=0 и changed=0;
3. защищённые области по guard-списку контракта: fenced-блоки,
   YAML-frontmatter и инлайн-код (построчно) — содержимое не изменено;
   снятие utm/referrer внутри URL-спанов — документированное поведение,
   нарушением не считается;
4. rc и конверт CLI `humanizer-clean --json` соответствуют контракту.

Любое нарушение 1–4 = ПОТЕРЯ, публикуется. Компаратор по-прежнему
отсутствует (публикуется как отсутствие).
