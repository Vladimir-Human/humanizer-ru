# Решения паритета сред Python ↔ JavaScript (2026-09-06)

Python (CLI/пакет) и JavaScript (браузерное демо) совпадают построчно на
общих векторах: `tests/fixtures/demo-parity/vectors.json`, гейт
`scripts/check_demo_parity.py` сверяет идентификатор, класс, количество,
номер строки, координаты и признак тени у обеих сторон с эталоном.
Семантические решения зафиксированы здесь; ни одна сторона не меняется
в одностороннем порядке — изменение решения обновляет этот файл, векторы
и генератор одним коммитом.

1. Цифры `\d`: Unicode-категория Nd в обеих средах. В JS переносится как
   `\p{Nd}` с флагом `u` (генератор `demo/generate_js_rules.py`).
   Арабско-индийские цифры (U+0661) ловятся одинаково.
2. Словесный символ `\w`: Unicode (L, N, M и подчёркивание) в обеих
   средах; в JS — `[\p{L}\p{N}\p{M}_]` с флагом `u`.
3. Пробельный `\s`: явный единый класс пробельных Python re (без
   `\ufeff`, который JS `\s` включает, а Python — нет); генератор
   переносит класс явно, «родной» `\s` сред не используется.
4. Граница слова: `\b`/`\B` в исходных паттернах ЗАПРЕЩЕНЫ — генератор
   отказывает в переносе (в JS граница всегда ASCII, в Python — Unicode).
   Границы пишутся явными lookaround-классами `(?<![A-Za-z0-9_])` /
   `(?![A-Za-z0-9_])`. Зафиксированное следствие: латинский токен,
   склеенный с кириллицей («вставкаattributableIndex»), ловится обеими
   средами — детекция не сужается.
5. Разбиение строк: набор разделителей Python `str.splitlines` (`\n`,
   `\r`, `\r\n`, `\v`, `\f`, U+001C–U+001E, U+0085, U+2028, U+2029);
   `demo/engine.js` реализует то же разбиение с абсолютными офсетами.
   Маркер после U+2028 — на строке 2 в обеих средах.
6. Нормализация: каждая строка приводится к NFC перед сопоставлением в
   обеих средах. Координаты `start`/`end` — кодовые точки внутри
   NFC-строки (для теневых находок — внутри теневой строки); JS переводит
   UTF-16-индексы в кодовые точки, астральные символы координаты не
   сдвигают. Абсолютные UTF-16-офсеты подсветки демо для теневых находок
   и NFC-изменений длины — приближение в пределах строки (документировано
   в шапке engine.js).
7. Маскирование URL: правила без флага `url_marker` сопоставляются со
   строкой, где URL-спаны заменены пробелами той же длины; с флагом — с
   исходной строкой. Флаг вычисляется границей детектора
   (`check_markers._is_url_marker`), публикуется в реестре
   `markers.v1.json` и переносится в правила демо — классификация не
   дублируется в JS.
8. Теневой проход: один и тот же класс невидимых символов
   (`_SHADOW_INVISIBLES`, включая астральный диапазон тегов
   U+E0000–U+E007F); находка в тени помечается `shadow: true`, имена,
   уже пойманные напрямую, не дублируются.
9. Вложенные дубли: совпадение, целиком лежащее внутри более длинного
   совпадения другого правила, отбрасывается; итоговая сортировка
   `(start, end, rule)` в обеих средах.

Невоспроизведённые заявления фиксируются без правки: краш MCP-сервера на
суррогате в `id` запроса не подтверждён — сессия продолжается, поведение
закреплено тестом `tests/test_interface_edges.py`.
