## Метрики одного прохода (tools/f8_measure.py)

1. F8c ROC стратифицированная: скор = rep0_total мягких сигналов; позитивы
   S1/S2, негативы S3+S4; AUC Манна-Уитни + бутстрэп ДИ 1000 по стратам
   (S1 против human, S2 против human, machine-all против S3 и против S4).
2. F12 excess-vocabulary: топ-5 дельт частот токенов machine против human;
   кандидат-маркер включается только при ΔAUC >= 0.02 на hold-out (вторая
   половина страт) И нулевых находках на human-hold-out; иначе публикуется
   отрицательный результат в METRICS (без включения в детектор).
3. F8d документ-оси: синтетические docx-фикстуры осей метаданных (creator,
   revision, TotalTime, rsid, company) через tools/docx_evidence.py;
   детектируемость каждой оси как hard-контекста («контекст, не вердикт»).
4. F8a+F11 baseline сигнатур: операторы с retention d3 >= 0.9 из снимка
   F3v2 (research/adversarial-2026-09/result.json) — таблица мониторинга.
5. Sensitivity S5: recall ожидаемой сигнатуры (meta.sig) на blob'ах с
   Wilson 95% CI по каждой сигнатуре (закрывает ЭТАП 3.1, Б1 частично).
6. F16b FP тяжёлого домена: доля текстов S4 с находками классов A/B,
   overall и по поддоменам, Wilson 95% CI (закрывает 2.4/П5 совместно с
   лёгким доменом F16).

## Цели и пороги (до прогона)

- F8c: AUC machine против S3 выше 0.7 хотя бы для одного поколения ИЛИ
  явная публикация «детектор не разделяет машинность мягкими сигналами»
  (тогда позиция THREAT-MODEL подтверждается, а не опровергается).
- F12: порог включения ΔAUC >= 0.02 и FP-human-hold-out = 0 (как выше).
- Sensitivity S5: recall ожидаемой сигнатуры не ниже 0.9 по сигнатурам
  классов A (маркеры копипасты детектируют свои артефакты).
- F16b: верхняя граница Wilson тяжёлого домена публикуется любой; цель
  согласована с F16 (лёгкий домен не выше 0.02), тяжёлый может быть выше —
  обе цифры идут в README/METRICS/llms.txt по П6/2.4.
- Ниже порогов — публикация как есть с планом в BACKLOG; задним числом
  ничего не чинится.
