# RELEASE.md — регламент выпусков

Каденс и правила релизного цикла humanizer-ru. Числа и факты — из
`eval/facts/facts.v1.json` и `METRICS.md`; этот документ правил не меняет,
он их собирает в одном месте.

## Семантика версий (SemVer-нарезка, обязательна)

- **patch** (x.y.z+1): только восстановление обещанного поведения
  (hotfix); без новых возможностей; совместимость с предыдущей
  опубликованной версией обязательна и проверяется гейтом.
- **minor** (x.y+1.0): только аддитивное (новые режимы, гейты, файлы,
  схемы); поведение по умолчанию не меняется; compatibility-тест против
  предыдущей опубликованной версии — часть релизного цикла.
- **major / несовместимая семантика** (Markdown-защита по умолчанию в
  polish, смена семантики `--genre`, переименование режимов): отдельный
  релиз с migration note в CHANGELOG и README; не смешивается с
  аддитивным минором. Один релиз = одна группа риска.

## Каденс

- Релизы — по мере надобности, не по календарю: релиз начинается
  предрегистрацией/отдельным решением сопровождения (или его делегированием), а не
  датой.
- Ежемесячно 1-го числа: ветка `metrics-YYYY-MM` со снимком `METRICS.md`
  (звёзды, форки, загрузки, внешние issue/PR — ноль публикуется как ноль).
- Красный CI чинится в день обнаружения (патч-ветка или прямая правка
  main с немедленным PR).
- Ежеквартально: `last_reviewed` в SKILL.md и пересмотр `next_review_due`.
- Первый запуск слепого агентного опроса — 2026-10-01, далее ежемесячно
  (предрег `research/survey-prereg-2026-09.md`).

## Релизный цикл (порядок шагов, проверен на v3.16.11—v3.18.0)

1. Ветка `release-x.y.z` от main; правки; все гейты зелёные
   (`scripts/check_all.py`, unittest, strict-publication, скан
   приватных токенов diff).
2. PR → CI зелёный → merge.
3. Подписанный аннотированный тег (GPG, ключ владельца) → push.
4. Release с детерминированным архивом `humanizer-ru.zip`
   (`scripts/check_release.py --build`; sha256 локальной сборки =
   CI-артефакт = ноты Release).
5. release-check на теге: SUCCESS (гейт «контракт выпуска» требует
   опубликованного Release — при первом прогоне допустим rerun после
   создания Release).
6. PyPI: Trusted Publishing (workflow `pypi-publish.yml`, PEP 740), если
   доверенный издатель настроен на стороне PyPI; иначе вручную twine из
   чистого клона тега. Настройка издателя — действие владельца в web-UI
   PyPI (API настройки не несёт).
7. Смоук чистой venv: установка опубликованной версии, `--version` всех
   команд, `--contract`, конверт ошибки, out-of-scope; `--sdist-test` на
   опубликованном sdist (тесты + зонды, включая MCP-точку входа).
8. Pages: demo-pages SUCCESS + `scripts/check_pages_router.py
   --live-pages` (машинные пути, включая /.well-known/llms.txt,
   identity.v1.json, og-image.png, sitemap.xml).
9. Скан логов Actions и diff на приватные токены; запись в RUNLOG.
10. Пауза между публикациями — по отдельному решению сопровождения (приказ о финальном
    финальный релизный цикле 2026-09-03 отменил обязательные 24 ч; мониторинг CI и
    реакций остаётся обязательным).

## Запреты релизного цикла

- force-push и переписывание истории запрещены; исключение — теги младше
  суток и только с записью в CHANGELOG.
- Числа в витрине — только из реестра фактов; без даты величина не
  цитируется.
- Перемеривание ради порога (optional stopping) запрещено.
- Публичные ветки и логи CI не несут приватных токенов (числа
  неотобранных прогонов, локальные пути, внутренние роли).

Единица бюджета витрины: гейт `check_docs.py` (I.18) меряет СИМВОЛЫ: SKILL.md ≤ 15750 символов (≈4500 токенов при оценке 3.5 символа/токен), README.md ≤ 320 строк, README.en.md ≤ 300, GOVERNANCE.md ≤ 98.

Trusted Publishing: доверенный издатель настроен владельцем 2026-09-04 (owner Vladimir-Human, repo humanizer-ru, workflow pypi-publish.yml, environment pypi); работоспособность доказана сухим прогоном workflow_dispatch 2026-09-04 (run 33794879701): OIDC-авторизация успешна, существующие файлы пропущены (skip-existing). twine остаётся запасным путём на случай отказа OIDC.
