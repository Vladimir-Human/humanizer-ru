# humanizer-ru-eval

Нейтральный корпус для проверки скиллов, находящих следы машинной генерации в
русском тексте. Любой скилл-кандидат прогоняет корпус одной командой.

## Состав

- **human** — 10 человеческих текстов (классика, поэзия, Конституция, Википедия,
  Викиновости). Ожидание: 0 совпадений.
- **boundary** — 2 контроля границ ложных срабатываний (benign wiki ref, emoji
  ZWJ). Совпадения заявлены и ожидаемы.
- **ai** — 12 сырых ответов (GigaChat, Алиса, Le Chat). Совпадения
  зафиксированы, единственное известное — BOM в raw-файле Le Chat.

Manifest: `manifest.v1.json` с sha256 каждого файла. Корпус замораживается
до прогона кандидатов; дрейф файла = ошибка hash.

## Прогон

```sh
# Reference-кандидат (regex из check_markers.py):
python3 eval/run_eval.py

# Внешний скилл-кандидат (runner: stdin — путь, stdout — JSON-список совпадений):
python3 eval/run_eval.py --candidate /path/to/runner.py
```

Результат — JSON со сводкой: число файлов, hash-несовпадения, ложные
срабатывания на human-корпусе, неожиданные совпадения на boundary. Код
возврата: 0 — чисто, 1 — есть проблемы.

## Принципы

- Не суммировать мягкие стилистические признаки в «процент ИИ».
- B-маркеры — не самостоятельный вердикт.
- Не средство обхода детекторов.
