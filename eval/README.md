# Слепое сравнение

Здесь проверяется главное: становится ли русский ИИ-текст лучше с этим навыком, чем
с другими навыками и чем с простой просьбой, и не теряются ли при этом факты.

## Что сравниваем

| Участник | Что это |
|---|---|
| `ours` | этот навык, `skills/humanizer-ru` |
| `old_v3` | прошлая версия 3.36.4 (тег `v3.36.4`) |
| `ilyautov` | [ilyautov/humanizer-ru](https://github.com/ilyautov/humanizer-ru), коммит в `systems.json` |
| `blader` | [blader/humanizer](https://github.com/blader/humanizer), самый популярный англоязычный навык |
| `smixs` | [smixs/humanizer-ru](https://github.com/smixs/humanizer-ru) |
| `prompt` | без навыка, одна строка: «Отредактируй присланный текст живым и естественным русским языком: убери канцелярит и штампы нейросети, сохрани все факты, числа, имена и оговорки без изменений» |

## Как устроено

1. **Тексты** (`corpus/`). 24 текста написали 11 моделей по обычным просьбам с фактами
   внутри (пост, письмо, карточка товара, инструкция, статья и другое, `briefs.json`),
   6 — сохранённые ответы Алисы, GigaChat, DeepSeek, Grok, Bing и Gemini, 6 — ловушки:
   человеческие тексты (Чехов, Гиляровский, Герцен, Википедия, Викиновости) и статья
   Конституции. В трёх текстах есть мусор вставки (utm, contentReference, невидимые
   символы). Ещё 12 текстов (`d01`–`d12`) — отдельный набор для настройки навыка;
   в итоговой таблице их нет.
2. **Исполнитель.** Один и тот же для всех: Claude Sonnet 5.5. Навык передаётся так, как
   его видит агент: SKILL.md в системной подсказке, остальные файлы навыка открываются
   инструментом `read_file`. Скрипты навыков не запускаются (у всех одинаково). Просьба
   пользователя одна на всех: «Очеловечь этот текст. В ответе дай только готовый текст,
   без пояснений и комментариев».
3. **Судьи.** Gemini 4 Argon и GPT-6.1 Sol — модели других лабораторий, чем исполнитель.
   Варианты перемешаны и названы буквами; каждый текст каждый судья оценивает дважды
   в разном порядке. Главный вопрос: какой вариант вы бы отправили с наименьшей
   доработкой. Судья также выписывает ошибки фактов, следы ИИ и ошибки языка.
4. **Факты.** Ошибка засчитывается, если её отметили не меньше половины проходов судей
   (и хотя бы два). Отдельно `skills/humanizer-ru/scripts/check_facts.py` сверяет каждый
   вариант с исходником.

## Пороги «полезен»

- ошибок фактов не больше 1 на весь корпус;
- выше простой просьбы хотя бы в 60% проходов;
- не хуже лучшего конкурента (не меньше 50% проходов);
- ловушки: без ошибок фактов хотя бы 5 из 6.

## Как повторить

Нужны `FAL_KEY` (вызовы через fal OpenRouter) и `gh`. Расходы считает
`.cache/spend.json`, потолок `EVAL_BUDGET_USD` (по умолчанию $15).

```sh
cd eval
python build_corpus.py --legacy <папка с research/ из тега v3.36.4>   # тексты уже лежат в corpus/
python fetch_systems.py
python run_systems.py --run final --set test
python judge.py --run final
python report.py --run final
```

Честно о том, как получился итог. После `final-1` судьи большинством отметили 8 наших
текстов с ошибкой смысла; разбор показал сдвиги модальности («может увидеть» →

правка навыка общая, не под конкретные тексты, но это стоит иметь в виду. Ещё одна
поправка: в `final-1` у ilyautov на тексте `r01` исполнитель вернул пустой ответ (сбой
стенда, а не их навыка); в `final` этот текст для них перезапущен и оценён заново.

судей лежат рядом: `outputs/`, `runs.jsonl`, `judgments.jsonl`. Расходы на API за всё:
$12.71 (`.cache/spend.json` в репозиторий не попадает).

## Ограничения

- Судьи — модели, а не люди. Они расходятся между собой: GPT-6.1 Sol заметно чаще
  награждает бережную правку, Gemini 4 Argon — более глубокую.
- Исполнитель один (Sonnet 5.5). На других моделях результат может быть другим.
- Навыки работают без своих скриптов; навыки, которые полагаются на скрипты, в
  реальной среде могут работать лучше.
- 36 текстов — это ориентир, а не статистика на все случаи.
