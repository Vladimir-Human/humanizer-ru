# humanizer-ru-eval

Нейтральный корпус для проверки скиллов, находящих следы машинной генерации в
русском тексте. Любой скилл-кандидат прогоняет корпус одной командой.

## Состав

- **human** — 11 человеческих текстов замороженного манифеста (классика, поэзия,
  Конституция, Википедия, Викиновости). Ожидание: 0 совпадений. Каталог
  `research/validation/human` шире манифеста (26 файлов): новые жанры проходят
  `check_corpus.py` сразу, а в манифест входят при его осознанном пересмотре.
- **boundary** — 2 контроля границ ложных срабатываний (benign wiki ref, emoji
  ZWJ). Совпадения заявлены и ожидаемы.
- **ai** — 12 сырых ответов (GigaChat, Алиса, Le Chat). Совпадения
  зафиксированы, единственное известное — BOM в raw-файле Le Chat.

Manifest: `manifest.v1.json` с sha256 каждого файла. Корпус замораживается
до прогона кандидатов; дрейф файла = ошибка hash.

## Прогон

```sh
# Reference-кандидат (regex из check_markers.py):
python3 eval/run_eval.py

# Внешний скилл-кандидат (runner: argv[1] — путь файла, stdout — JSON-список совпадений):
python3 eval/run_eval.py --candidate /path/to/runner.py
```

Результат — JSON со сводкой: число файлов, hash-несовпадения, ложные
срабатывания на human-корпусе, неожиданные совпадения на boundary. Код
возврата: 0 — чисто, 1 — есть проблемы, 2 — отказ инструмента (в т.ч.
когда раннер-кандидат упал более чем на трети файлов корпуса; одиночный
сбой раннера пишется в `details` как `runner_error` и находкой не считается).

## Триггер-эвал границы активации (`run_triggers.py`)

Детерминированный гейт границы активации скилла: 10 позитивных запросов
(формулировки из description SKILL.md обязательно присутствуют в нём) и
8 near-miss (код, английский, юридический документ — не должны совпадать
с фразами-активаторами). Падает кодом 1, если хоть одна scope-фраза
description пропала из SKILL.md; предупреждает (но проходит), если
near-miss случайно совпал. Кейсы — встроенный список, без LLM:
`python3 eval/run_triggers.py` (в CI), `--selftest` — умеет падать.

## Сценарные эвалы (`scenarios/evals.v1.json`)

Карта сценарных эвалов уровня скилла для будущего слепого протокола:
каждый кейс `{"id", "kind", "input", "expectations", "forbidden"}` кодирует
«не портить живое»/«не дописывать факты» в проверяемые условия — кейсы
guard (clean-human-text-guard, quotes-trap, audit-only), ловушки
(slop-swap-trap, meta-commentary-trap, tail-negations, ru-en-mix,
term-preserve), плотность фактов (fact-density), краткость
(short-form-push, brevity) и функциональные элементы (functional-elements).
Карта метрик — сами условия в `expectations`/`forbidden`, без новых фактов.
LLM-судейство подключено: прогон панели судей 2026-08-25 — в
`scenarios/run-2026-08-25/` (REPORT.md).

## Детектор-харнес «до/после» (`detect_eval.py` + `detectors/`)

Порт измерительного харнеса ilyautov/humanizer-ru (MIT, атрибуция в docstring
каждого файла) — измеряет, как правка меняет детектируемость текста на
существующих парных прогонах `eval/runs/<run>/` (`source/` = «до», `with/` =
«после»). Прогон — отдельный артефакт поверх замороженного run: `run_sha256`
не трогается.

**Детекторы — ОТНОСИТЕЛЬНАЯ метрика, никогда вердикт.** Публикуются только
относительные дельты до/после с FP-контролем; абсолютные «% обхода» и
обещания «не детектируется» запрещены (см. «Принципы»).

- `detect_eval.py <run_dir>` — детектор-харнес: скорит пары всеми доступными
  детекторами, считает среднюю дельту и долю пар «после ниже до», пишет JSON
  (`--json out.json`) и человекочитаемую сводку. Гейты зачёта: изменение длины
  на каждой паре (флаг `after_longer_20pct`, НЕ исключение — new_facts уже
  проверен blind_eval); регрессия по направлению текста (AI-пары: дельта ≤ 0;
  human-пары: рост средней дельты > +0.1 — предупреждение).
- **Модель и её версия обязательны в отчёте** (имя + слепок digest из
  `/api/tags`): дельта сравнима только в пределах одного детектора и одной
  даты.
- **FP-аудит обязателен** в каждом прогоне: скор детектора на 11 human-текстах
  манифеста (`eval/manifest.v1.json`); `score >= 0.5` на human = ложное
  обвинение; блок «FP-аудит: K/11 ложных обвинений». Без него ось = маркетинг.
- **detect_eval.py гоняет только локальные детекторы**: текст не покидает
  машину (нет ключей/ToS/сети наружу — нужен только демон Ollama).
  Облачные серии лидерборда (LEADERBOARD.md) публикуются отдельным протоколом. Перплексия
  (`ollama_ppl`) — приближённая оценка по выборке, чужая калибровка, включается
  только флагом `--perplexity` и в вердикты/лидерборд не идёт.
- Ноль доступных детекторов → код 2 «нет доступных детекторов: отчёт не
  создан» (fail-closed, не пустой отчёт). `--selftest` проверяет
  детерминированную логику агрегации и формат FP-блока без Ollama (в CI
  запускается только он).

Запуск:
```sh
python3 eval/detect_eval.py <run_dir> --json eval/detect-results/<date>-detect-<run>.json
python3 eval/detect_eval.py --selftest
```

## Принципы

- Не суммировать мягкие стилистические признаки в «процент ИИ».
- B-маркеры — не самостоятельный вердикт.
- Снижение статистических следов — измеримая цель: публикуются относительные
  дельты детектируемости до/после с FP-контролем; абсолютные «% обхода»
  и обещания «не детектируется» не публикуются.
