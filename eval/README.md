# Слепое сравнение

Проверяем одно: становится ли русский текст после нейросети лучше с этим навыком, чем с
другими навыками и с простой просьбой, и не теряются ли при этом факты.

## Последний замер: версия 4.1.0, 15.10.2026

Сначала на GitHub нашлись все заметные навыки, которые обещают убрать следы нейросети из
текста: три самых популярных английских и девять русских. Чтобы не платить за полный прогон
каждого, был отбор: 12 текстов из набора для настройки (`d01`–`d12`), три группы по шесть
навыков, в каждой наш навык и ilyautov/humanizer-ru как точки отсчёта. В финал вышли те,
кто в своей группе оказался выше ilyautov хотя бы в половине оценок, и blader/humanizer как
самый популярный навык (57 тыс. звёзд).

Финал прошёл на 30 текстах, которых не видела ни одна версия навыка: 24 свежих текста
одиннадцати моделей по новым просьбам (`n01`–`n24` в `corpus/briefs.json`) и шесть ловушек
(человеческие тексты и статья Конституции). Судили Gemini 4 Argon (два прохода в разном
порядке вариантов) и Kimi K3 (один проход). GPT-6.1 Sol в этот раз не участвовал по
решению владельца.

На шести ловушках наш навык снова оказался лучшим: среднее место 2.5 из 8, ошибок смысла
нет. Простая просьба испортила четыре из шести.

**Судьи расходятся.** Gemini 4 Argon ставит наш навык первым с заметным отрывом (2.67;
ilyautov 3.52, avoid-ai-writing-russian 3.56). Kimi K3 ставит первым
avoid-ai-writing-russian (3.17), наш навык вторым (3.92). Порядок любой пары вариантов
у двух судей совпадает в 71% случаев, у Argon с самим собой в другом проходе — в 85%.
Поэтому против avoid-ai-writing-russian честнее говорить о близком результате, а не о
победе.

**Четыре наших текста с ошибкой смысла.** Два спорных: убран блок советов чат-бота
дизайнеру (`n12`), убрана формула «благодарим за понимание» (`n13`). Два настоящих: в
HTML-разметке сняты теги `<strong>` и список свёрнут в фразу (`n21`), в анонсе лекции
выпало обещание рассказать о фасадах по дороге на работу (`n24`). Это следующие
доработки.

**Сбой стенда.** На самом длинном тексте (`n05`, 25 тыс. знаков) ответ нашего навыка
упёрся в лимит 8000 токенов и оборвался. Лимит поднят до 16 000 для всех, остальные
участники до него не доходили, поэтому заново прогнан только наш навык на `n05`, и этот
текст оценён заново всеми судьями. Обрезанный ответ и прежние оценки сохранены локально
(`*.bak`, в репозиторий не попадают).

Пороги для 4.1.0: выше простой просьбы — выполнено (67%), не хуже лучшего конкурента —
выполнено (54%), ловушки — выполнено (6 из 6), ошибок смысла не больше одной — **не
выполнено** (4; у ilyautov и pishi-normalno по 3). Полные таблицы: `results/final2/summary.md`
(оба судьи), `summary-gemini-4-argon.md`, `summary-kimi-k3.md`.

## Как устроено

1. **Тексты** (`corpus/`). Наборы: `dev` (12 текстов) — только для настройки навыка;
   `test` (24 текста 11 моделей, 6 сохранённых ответов Алисы, GigaChat, DeepSeek, Grok,
   Bing и Gemini, 6 ловушек) — замер 4.0.0; `holdout` (24 текста `n01`–`n24`) — замер
   4.1.0. В нескольких текстах есть мусор вставки (utm, contentReference, невидимые символы).
   Правило: навык настраивается только на `dev`; набор, по ошибкам которого правили
   навык, для следующего публичного замера заменяется новым.
2. **Исполнитель** один для всех: Claude Sonnet 5.5. Навык передаётся так, как его видит
   агент: SKILL.md в системной подсказке, остальные файлы открываются инструментом
   `read_file`. Скрипты навыков не запускаются, у всех одинаково. Просьба одна: «Очеловечь
   этот текст. В ответе дай только готовый текст, без пояснений и комментариев». Лимит
   ответа 16 000 токенов.
3. **Судьи** из других лабораторий, чем исполнитель. Варианты перемешаны и названы буквами.
   Главный вопрос: какой вариант вы бы отправили с наименьшей доработкой. Судья также
   выписывает ошибки фактов, следы ИИ и ошибки языка. Текст задания судьям — `PROMPT` в
   `judge.py`.
4. **Факты.** Ошибка засчитывается, если её отметили не меньше половины проходов (и хотя
   бы два). Отдельно `skills/humanizer-ru/scripts/check_facts.py` сверяет каждый вариант с
   исходником (колонка «Ошибки скрипта сверки» в сводках; скрипт ловит и законное удаление
   служебного текста чат-бота, поэтому это подсказка, а не приговор).

## Пороги «полезен»

- ошибок смысла не больше 1 на весь набор;
- выше простой просьбы хотя бы в 60% оценок;
- не хуже лучшего конкурента (не меньше 50% оценок);
- ловушки: без ошибок смысла хотя бы 5 из 6.

## Как повторить

Нужны `FAL_KEY` (вызовы через fal OpenRouter) и `gh`. Расходы считает `.cache/spend.json`,
потолок `EVAL_BUDGET_USD` (по умолчанию $15).

```sh
cd eval
python build_corpus.py --legacy <папка с research/ из тега v3.36.4>   # тексты уже лежат в corpus/
python fetch_systems.py                          # или только нужные: fetch_systems.py ilyautov blader
python run_systems.py --run final2 --set holdout --systems ours,prompt,ilyautov
python judge.py --run final2 --judges google/gemini-4-argon --rounds 2
python report.py --run final2
python report.py --run final2 --judges google/gemini-4-argon   # оценки одного судьи, отдельный файл
```

оказались настоящими сдвигами уверенности и охвата, их разбор лёг в 4.1.0.

## Ограничения

- Судьи — модели. Живых редакторов среди них не было.
- Исполнитель один (Sonnet 5.5). На других моделях результат может быть другим.
- Навыки работают без своих скриптов. Те, что полагаются на скрипты, в реальной среде
  могут работать лучше.
- 24 текста в финале — ориентир. Разница с avoid-ai-writing-russian меньше разброса между
  судьями.
