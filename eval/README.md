# Слепое сравнение

Проверяем одно: становится ли русский текст после нейросети лучше с этим навыком, чем с
другими навыками и с простой просьбой, и не теряются ли при этом факты.

## Замер final4 (сокращённый): правила записаны 21.10.2026, до текстов набора `holdout3`

**Что проверяем.** Кандидат (ветка `candidate/wiki-markers`, коммит 98cf8cc) — это 4.1.1 плюс
признаки из статьи Википедии: хвост `utm_source=openai` при метках автора, «в предоставленных
результатах поиска», «Это не про X, это про Y», «В заключение…», «Несмотря на успехи… вызовы…
перспективы», «застанет вас в добром здравии». Вопросы: не стал ли он хуже 4.1.1 и где мы против
ilyautov/humanizer-ru v3.32.0 (вышла 19.10).

**Почему сокращённый.** Бюджет API почти исчерпан ($37.06 из $38). Решение владельца 21.10:
Gemini 4 Argon — только по сокращённой программе; GPT-6.1 Sol и MiniMax через DSH бесплатны;
Sonnet 5.5 и Opus 5.5 — с лимитов подписки Claude; платные модели через DSH не используются.
Сильными в текстах владелец считает только Sonnet 5.5, Opus 5.5 и Argon, поэтому места
расставляют только Argon и Opus.

- **Набор `holdout3`** (`q01`–`q12`): 12 жанров, список и задание — `corpus/holdout3-briefs.md`.
  Просьбы написал GPT-6.1 Sol одним запросом, они не правились. Тексты `q03`, `q06`, `q09`, `q12`
  написала Gemini 4 Argon, остальные — Sol (через DSH с ролью «обычный чат-ассистент»: агент DSH

- **Участники:** `ours` — кандидат 98cf8cc, `ours411` — 4.1.1 (тег `v4.1.1`), `ilyautov332` —
  ilyautov/humanizer-ru v3.32.0 (3621b1c). Простой просьбы и avoid-ai-writing-russian в этот раз нет.
- **Исполнитель:** Claude Sonnet 5.5 субагентами Claude Code (`batches.py`), не через API.
  Системная подсказка и просьба те же, что у API-исполнителя, только файлы навыка открываются

- **Судьи.** Места, доли и «готов к отправке» — Gemini 4 Argon (один проход через fal) и
  Claude Opus 5.5 (субагенты Claude Code, тот же `PROMPT`, пачки по 6 текстов). Ошибки смысла —

  - тексты с ошибкой смысла: не больше одного на 12 ИИ-текстов и не больше, чем у самого

  - не хуже ilyautov332: не меньше 50% сравнений;
  - не хуже `ours411`: не меньше 50% сравнений и ошибок смысла не больше;
  - ловушки: без ошибок смысла хотя бы 5 из 6.
- **Пробы** `p01` (ответ чат-бота) и `p02` (статья) написаны вручную под новые правила и судьям не
  показываются. Кандидат проходит их, если:

## Как устроено

1. **Тексты** (`corpus/`). Наборы: `dev` (12 текстов) — только для настройки навыка;
   `test` (24 текста 11 моделей, 6 сохранённых ответов Алисы, GigaChat, DeepSeek, Grok,
   Bing и Gemini, 6 ловушек) — замер 4.0.0; `holdout` (24 текста `n01`–`n24`) — замер

   нескольких текстах есть мусор вставки (utm, contentReference, невидимые символы).
   Правило: навык настраивается только на наборах, которые уже не дают публичных цифр;
   набор, по ошибкам которого правили навык, для следующего публичного замера заменяется
   новым.
2. **Исполнитель** один для всех: Claude Sonnet 5.5. Навык передаётся так, как его видит
   агент: SKILL.md в системной подсказке, остальные файлы открываются инструментом
   `read_file`. Скрипты навыков не запускаются, у всех одинаково. Просьба одна: «Очеловечь
   этот текст. В ответе дай только готовый текст, без пояснений и комментариев». Лимит
   ответа 16 000 токенов.
3. **Судьи** из других лабораторий, чем исполнитель. Варианты перемешаны и названы буквами.
   Главный вопрос: какой вариант вы бы отправили с наименьшей доработкой. Судья также
   выписывает ошибки фактов, следы ИИ и ошибки языка. Текст задания судьям — `PROMPT` в
   `judge.py`. Ответы Kimi K3 с одной лишней скобкой `judge.py` чинит; ответ, который не
   разобрать, повторяется при следующем запуске.
4. **Факты.** Ошибка засчитывается по большинству судей (раздел «Пороги»). Отдельно `skills/humanizer-ru/scripts/check_facts.py` сверяет каждый вариант с
   исходником (колонка «Ошибки скрипта сверки» в сводках; скрипт ловит и законное удаление
   служебного текста чат-бота, поэтому это подсказка, а не приговор).

## Пороги «полезен»

Правила второй редакции зафиксированы 15.10.2026, до того как появились тексты набора
`holdout2`, и действуют с замера 4.1.1.

**Судьи.** Три модели из трёх разных лабораторий: Gemini 4 Argon (Google, два прохода в
разном порядке), Kimi K3 (Moonshot), Muse Spark 1.3 (Meta). У каждого судьи один голос:
его проходы сначала усредняются. Muse Spark выбран как самая сильная по индексу
Artificial Analysis (48 на 15.10.2026) модель из лабораторий, которых ещё нет на стенде;
GPT-6.1 Sol (OpenAI) пока не используется по решению владельца.

**Ошибка смысла** засчитана, если её отметило большинство судей (двое из трёх). Судья
отмечает текст, если нашёл ошибку хотя бы в половине своих проходов. В сводке рядом
стоит и число текстов, где ошибку увидел хоть один судья: это подсказка, где смотреть
глазами, а не порог.

Пороги для нашего навыка:

- тексты с ошибкой смысла: не больше одного на 12 ИИ-текстов (2 на 24) и не больше, чем
  у самого аккуратного из остальных участников;
- выше простой просьбы хотя бы в 60% сравнений;
- не хуже лучшего конкурента: не меньше 50% сравнений;
- не хуже прошлой версии: не меньше 50% сравнений и ошибок смысла не больше;
- ловушки: без ошибок смысла хотя бы 5 из 6.

**Почему правила поменялись.** До 4.1.0 ошибка засчитывалась по двум проходам из трёх, а
два прохода были у одного судьи. Получалось, что Argon подтверждал ошибку один, а то, что
видел только второй судья, не засчитывалось никогда. Средние места считались по проходам,
то есть у Argon был двойной вес. Порог «не больше одной ошибки на весь набор» лежал ниже
шума: ilyautov/humanizer-ru, который почти не трогает текст, получил 3 ошибки на 24
текстах, а судьи расходились, считать ли ошибкой удаление советов чат-бота. По новым
правилам 4.1.0 тоже не проходит: у нас 3 текста с ошибкой, у avoid-ai-writing-russian и
pishi-normalno по 2, против avoid-ai-writing-russian ровно 50%
(`results/final2/summary-rule2.md`).

## Как повторить

Нужны `FAL_KEY` (вызовы через fal OpenRouter) и `gh`. Расходы считает `.cache/spend.json`,
потолок `EVAL_BUDGET_USD` (по умолчанию $15).

```sh
cd eval
python build_corpus.py --legacy <папка с research/ из тега v3.36.4>   # тексты уже лежат в corpus/
python fetch_systems.py                          # или только нужные: fetch_systems.py ilyautov blader
python run_systems.py --run final3 --set holdout2 --systems ours,ours410,avoidai_ru,ilyautov,prompt
python judge.py --run final3        # по умолчанию Argon (2 прохода), Kimi K3, Muse Spark 1.3
python report.py --run final3       # --prev ours410: порог «не хуже прошлой версии»
python report.py --run final3 --judges google/gemini-4-argon   # оценки одного судьи, отдельный файл
python report.py --run final3 --ours ours410 --prev ours --out summary-shipped
```

Сокращённый замер `final4`: исполнитель и судья Opus — субагенты Claude Code, Sol — через DSH.

```sh
python build_corpus.py --legacy <папка с research/ из тега v3.36.4>   # holdout3: Sol через dsh:, Argon через fal
python fetch_systems.py ours411 ilyautov332
python batches.py prepare-run --run final4 --systems ours,ours411,ilyautov332 --batches "q01,...,q06;q07,...,q12;h01,...,h06,p01,p02"
# по субагенту Sonnet на каждый .cache/batch/final4/<участник>/batchN.task.txt, затем:
python batches.py collect-run --run final4
python judge.py --run final4 --judges google/gemini-4-argon --texts <q01-q12,h01-h06>
python judge.py --run final4 --judges dsh:agentrouter-astra/gpt-6.1-sol --texts <те же> --workers 3
python batches.py prepare-judge --run final4 --judge claude-code/opus-5.5 --texts <те же> --batch-size 6
# по субагенту Opus на каждый batchN.task.txt судьи, затем:
python batches.py collect-judge --run final4 --judge claude-code/opus-5.5
python report.py --run final4 --prev ours411 --rank-judges google/gemini-4-argon,claude-code/opus-5.5
python patterns.py --run final4
```

Бесплатная дополнительная проверка без API: `python patterns.py --run final3` считает, сколько
шаблонов ИИ-текста из заранее записанного списка (`patterns.py`) было в исходниках, сколько
осталось у каждого участника и сколько он добавил (`results/<run>/patterns.md`). Оставшийся
шаблон бывает законным, поэтому это подсказка, где смотреть, а не оценка.

## Ограничения

- Судьи — модели. Живых редакторов среди них не было.
- Исполнитель один (Sonnet 5.5). На других моделях результат может быть другим.
- Навыки работают без своих скриптов. Те, что полагаются на скрипты, в реальной среде
  могут работать лучше.
- 24 текста в финале — ориентир. Только от судей счёт ошибок гуляет примерно на два текста
  (одни и те же ответы 4.1.0 в трёх циклах получили 2, 3 и 1).
- Muse Spark чаще других судей выбирает самую бережную правку; Gemini — более глубокую.
